# How Pace Bar works

Implementation details and limits of the displayed metrics. Commands on this page run from `PaceBar/`.

## Interface

The popover fits its contents without scrolling or a fixed height. The **Frontier** section has one ring per Codex identity (Codex 1–4), then one per Claude subscription (Claude 1, …); see [Frontier rings](#frontier-rings-and-pooled-forecast). Each shows independent remaining-quota meters, percentages, and compact reset intervals. The server determines available windows; a missing five-hour window is not invented. Exact resets, freshness, and errors are available on hover. Failed or stale readings are dimmed and marked; errors never become zero usage. Below the rings, **API equivalent · 7d** and **API equivalent · 30d** combine Codex and Claude usage priced at API list rates. Clicking either reveals both; each then shows a thin two-tone bar with the Codex (cobalt) and Claude (terracotta) split, exact amounts are on hover, and one caption below gives the legend and the “at API list prices, not billed” caveat. While hidden, no caveat is shown because there is no number to qualify. OpenRouter shows account-wide balance and **Spent · lifetime**. Nous shows the loaded model and generation speed in its header, GPU, CPU, VRAM, and RAM as rings, lifetime tokens as one bar split into cache, fresh input, and output (with the cached share of input), and a footer with recorded GPU energy, average power, and estimated GPU electricity cost. All cost amounts are blurred until clicked, can be hidden again, and hide when the popover closes. A fixed placeholder keeps concealed digits and their length out of both the view and accessibility tree.

The menu glyph has two styles, chosen under **Settings › Menu bar icon**; it switches immediately without refreshing data. Both are template images, so the menu bar tints them.

- **Bars** (default, 22 × 18 points): five upright level bars. Codex 1–4 come first; Claude 1 follows after a wider gap. Each bar is 12 points tall, so each of its twelve steps is one point. A Codex bar shows the most constrained ordinary allowance, excluding model-specific allowances. The Claude bar shows its most constrained window, either the 5-hour session or the weekly allowance. If both windows have reset and have not been used since, it is full. Claude readings are paced to respect Anthropic's rate limit, so they count as current for an hour; Codex readings count as current for ten minutes. An outage of one provider does not blank the other.
- **Orbit** (18 × 18 points): four separated rounded arc segments around an empty center, ordered Codex 1 at top, Codex 2 at right, Codex 3 at bottom, and Codex 4 at left, clockwise from 12 o'clock. Claude is not part of this style.

In both styles, a zero balance keeps its dim intact track, while unavailable data uses a broken, dotted track. The tooltip and accessibility label retain the current percentages even when a change is too small to move a pixel. The image updates only when those visible steps or the style change, reusing existing refresh work. No animation, extra timer, network request, or chart framework is involved.

We compared [three icon directions](images/icon-study.png) at menu-bar size: upright meters, interrupted horizontal rails, and separated arcs. Orbit, built from the separated arcs, came first. After Claude subscriptions were added, a later review compared six candidates next to typical menu-bar neighbors. Upright level bars became the default because they give Claude its own slot and make low accounts easy to compare. Orbit remains available because it matches the app icon.

The application bundle icon uses the same four 65-degree arcs and 25-degree gaps as Orbit, with a static mint mark on a dark teal rounded tile. It is identity artwork, not a quota reading. `scripts/make-icon.swift` renders all standard 1×/2× icon sizes through 1024 pixels; the packager generates `PaceBar.icns` and declares `CFBundleIconFile` before signing. Both development and Developer ID release builds include it.

Design references: Apple's [interface icon guidance](https://developer.apple.com/design/human-interface-guidelines/icons) supports simplified shapes, consistent stroke weight, and optical alignment. Its [chart guidance](https://developer.apple.com/design/human-interface-guidelines/charts) informed retaining explicit numeric values and context alongside meters. The implementation uses small native geometry instead of a chart framework. Account handling was informed by [CodexBar's account-scoping design](https://github.com/steipete/CodexBar/blob/main/docs/codex.md).

## Accounts and data fidelity

- Reads the configured Codex auth file (default `~/.codex/auth.json`) and existing `~/.codex-t3/*/auth.json` / `~/.codex-gui/*/auth.json` homes. Deduplicates `tokens.account_id`, selecting the most recently modified credential file for duplicate identities. Each request has that account's bearer token and `ChatGPT-Account-Id`; returned account IDs are checked when supplied. Display names come from home aliases: the configured auth home is Codex 1, then `second`, `last`, and `btc` homes are Codex 2, Codex 3, and Codex 4, in that order. Emails and account IDs are never rendered, including in tooltips. Credentials are never copied, refreshed, logged, or written. Expired sign-ins must be renewed in their owning Codex application.
- Read-only `GET https://chatgpt.com/backend-api/wham/usage` supplies subscription windows/resets. This is an undocumented service endpoint and can change. No API spend estimate or local token count is substituted for subscription quota.
- Claude reads enabled `anthropic` OAuth sign-ins from OMP's credential store (`~/.omp/agent/agent.db`) read-only, deduplicated by account and named Claude 1, Claude 2, … in sign-in order. Read-only `GET https://api.anthropic.com/api/oauth/usage` (the endpoint Claude Code and CodexBar use; undocumented and subject to change) supplies the five-hour and weekly windows; `utilization` is a percentage. A window without a reset has not started and is omitted. Model-scoped weekly lanes and extra-usage credits are not shown. Tokens are never refreshed or written: an expired sign-in shows an error until OMP renews it during normal use. Anthropic rate-limits this endpoint, so requests are paced: a reading OMP recorded in `usage_history` within the last four minutes is used instead of a request, a 429 pauses requests until `Retry-After` (ten minutes if absent) without showing an error, and the last reading is kept in `~/.local/share/pace-bar/claude-usage.json` so it appears immediately after a relaunch. A window whose reset has passed shows as refilled. The ring is marked only for a real error or a reading more than an hour old.
- OpenRouter reads an existing OpenCode API credential file (`~/.local/share/opencode/auth.json`) or a file containing `{"apiKey":"..."}`. `/api/v1/credits` supplies account-wide balance and lifetime credit spend. Key-specific period figures can be zero while other keys are active, so they are not presented as account spending. External BYOK provider bills are not included.
- Nous defaults to `http://nous:8080` over the existing private network. `/v1/models` selects only an already-loaded model, then `/metrics?model=...` reads its counters. No model is loaded or switched. Pace Bar collects observed lifetime totals by model and preserves them across app restarts in `~/.local/share/pace-bar/nous-history.json`; totals are scoped to the configured Nous origin. Input excludes cache; output is separate. The t/s field is the server's rate gauge, not an end-to-end latency or TTFT measurement. TTFT is not exposed by this host's metrics, so no fabricated value is shown. Totals begin with the currently available process counters, preserve known counter resets, and cannot recover prior ended-process usage, a model loaded and unloaded entirely between polls, or an unseen reset followed by larger counters.
- The optional [host API](../host/README.md) supplies NVIDIA/NVML or AMD/amdgpu utilization, VRAM, power, and GPU energy through the existing private network. AMD energy is an explicitly labeled persisted sampled-power estimate. Set `nousMetricsURL` to use it. With no metrics URL, SSH remains NVIDIA-only and collects GPU counters, `free -m`, and `/proc/stat` using existing noninteractive access, strict host verification, and no agent forwarding. CPU uses counter deltas; GPU power is not whole-host power.

Output, Input, and Cache token totals use compact K/M/B/T notation with at most one decimal place; stored counters retain their full precision.

## Cost and behavior

Cloud polls every five minutes (up to four Codex requests plus one OpenRouter request). Nous polls every minute (two inference HTTP requests plus one host HTTP request, or one short SSH command when the metrics URL is unset). Low Power Mode or serious/critical thermal state reduces these to fifteen and five minutes. One tolerant minute timer schedules work; the popover view is released when closed. Pause stops scheduling, sleep cancels refresh tasks, and resume refreshes. HTTP responses and SSH output are bounded; connections have timeouts. A running SSH sample may finish its bounded timeout after pause.

A local release sample on September 19, 2026, before token-cost history was added, measured a 728 KB app bundle and 13.3 MB physical footprint (13.8 MB peak), with 0.0% CPU in an idle `ps` sample. This is an earlier brief measurement, not a current resource or battery-life benchmark.

`electricityUSDPerKWh` is an optional numeric setting, kept local. GPU energy and its live-counter baseline are retained per Nous origin in the existing `nous-history.json`. NVIDIA begins with the available hardware counter; subsequent driver/host resets add a new counter without erasing retained energy. AMD via the host API uses a five-second sampled-power estimate, labeled **Wh (est.)**; the **Cost** beside it is derived from that estimate. Its host checkpoint and stable counter identity survive service/host restarts; replayed checkpoints are not counted twice. Switching collection methods preserves the total without adding overlapping history. Missing intervals and historical use before collection are not invented. Abrupt host shutdown can lose up to one uncheckpointed minute; energy between the last client observation and a hardware reset can also be lost. Keep the local history file to retain earlier epochs. Power-suspended GPUs may withhold live wattage while retained energy remains available. Avg W uses two valid readings within the same counter epoch; missing estimated-power samples can understate it. Cost is Wh / 1000 × USD/kWh, covering recorded GPU activity, not whole-host electricity or a billing month.

Nonsecret settings live in `~/.config/pace-bar/config.json`, created only when saved. Quota history and Nous lifetime totals are small local JSON files. There is no telemetry, cookie scraping, credential-refresh service, or updater.

### Independent API-equivalent cost

Pace Bar calculates uncached input × input price + cached input × cache-read price + cache creation × cache-write price + output × output price. OMP/Pi input excludes cache, so the reader normalizes it before pricing; native Codex input already includes cache. Reasoning is already included in output, never added again. This is a hypothetical API-price estimate, **not** a subscription bill, savings, quota consumption, or forecast. Missing prices remain unpriced; the tooltip reports excluded records and incomplete history. Unavailable costs display **—**, not a fabricated zero.

The 7-day and 30-day windows include today plus the preceding 6 or 29 calendar days in the Mac's time zone, including daylight-saving transitions. Neither is a subscription-reset window or calendar billing month. Usage accumulates as local clients record completed usage and ages out of each window independently; older history remains retained.

Direct sources are native Codex `sessions` and `archived_sessions` under the configured auth home, `~/.codex`, `~/.codex-t3/*`, `~/.codex-gui/*`, and configured T3 homes; plus OMP/Pi `sessions` under `~/.omp/agent`, `~/.pi/agent`, `~/.local/share/omp`, and `~/.omp/profiles/*/agent` / `~/.pi/profiles/*/agent`. Nested subagent sessions are included. Canonicalized roots are scanned once. OMP/Pi `openai-codex` and `openai` assistant usage feeds the Codex estimate; direct `anthropic` usage feeds the Claude estimate. Claude through OpenRouter or Antigravity, other providers, and local inference remain separate. Anthropic one-hour cache writes (`usage.cttl.ephemeral1h`) are priced at twice the base input rate; other cache writes use the catalog's five-minute write price. OMP files scanned before Anthropic support are rescanned once. Other machines and clients without supported local usage logs are not inferred.

Each refresh discovers new files and reads appended bytes after verifying a 64-byte FNV-1a guard. Unchanged files reuse usage metadata; replaced files are reparsed. Unfinished JSONL tails are reread until complete. OMP/Pi provider response IDs, or message IDs combined with timestamps/model/token counts, deduplicate copied and forked messages without collapsing distinct equal-token requests. Newest OMP/Pi files are prioritized ahead of native-history bootstrap. Cold scans checkpoint after a bounded amount of work and show partial coverage until caught up.

Local usage and both estimates refresh every minute, or every five minutes under power/thermal constraints, using the existing timer independently of cloud account polling. Manual Refresh bypasses the interval. Scanning runs off the UI actor. The tooltip shows the last usage-check time. A client must have written usage metadata before it can be counted; unreported in-flight tokens are not invented.

The compact owner-only archive is `~/.local/share/pace-bar/codex-cost-history.json`. Only usage metadata is retained, not prompts, responses, auth files, or credentials. An existing T3 scan cache may bootstrap historical records once; subsequent refreshes read source logs directly and do not let newer T3 snapshots replace the independent archive. Missing source files do not erase retained history. T3 does not need to be running or installed.

Pricing is owned by Pace Bar: a public LiteLLM catalog refresh is attempted at most daily and saved to `~/Library/Caches/pace-bar/litellm-pricing.json`. Bundled known OpenAI rates keep supported models priceable offline or when the catalog lacks them. T3's catalog and custom overrides are not read. Only the public catalog is downloaded; no usage is uploaded. These are standard/base-rate equivalents, not fast, flex, batch, or long-context invoices. The tooltip identifies the catalog date; updated prices can change historical estimates.

OpenRouter's `/credits` endpoint is lifetime credit spend, not trailing-30-day account activity. It stays explicitly labeled as actual lifetime spend. Local inference has no universal hosted equivalent: its GPU electricity estimate remains separate, covering retained observed energy rather than a guaranteed complete since-installation history.

## Validation

`make test` uses synthetic data and temporary files only. Coverage includes account separation, quotas, history migration/restart, deleted source retention, OMP-only usage without T3, appended and child sessions, copied messages, provider exclusions, guarded scans and unfinished tails, independent pricing, unknown prices, and 7/30-day calendar/DST boundaries.

`swift run PaceBarProbe` explicitly performs live read-only validation and prints only capability counts, not tokens, emails, account IDs, or raw bodies. `swift run PaceBar --render-preview /tmp/pace-bar.png` renders a synthetic panel without network requests. Root CodexBar tests remain upstream's separate suite.

`swift run PaceBarProbe --import-cost-history /tmp/pace-bar-cost-report.json` exercises the same automatic migration and catches up local scans without account probes or Keychain access. It creates an owner-only reconciliation report containing aggregate model tokens and estimated cost, not transcripts or identities; it refuses to overwrite an existing report. Normal onboarding does not require this diagnostic command. Remove the report after comparison.

## Frontier rings and pooled forecast

Each subscription is one ring, echoing the menu-bar Orbit. Each provider has one color family used for its rings and its cost share: cobalt for Codex, terracotta and sand for Claude, and mint greens for local inference; orange is reserved for warnings. A Codex ring shows the account's tightest ordinary allowance; the number in the center is its remaining percentage, and `↻ 3d` is when that allowance resets. The Claude ring nests the 5-hour session (inner, sand) inside the weekly allowance (outer, terracotta); the center shows whichever is lower, and `↻ 3h · 4d` lists the session reset, then the weekly reset. Stale or failed readings are dimmed and marked. Every window, its exact reset, and errors are on hover.

Below the rings, **Codex pool** is the plan-weighted share of all Codex capacity still available, with a forecast of when the whole pool runs out at your pace. Accounts are treated as one parallel pool because OMP balances work across every signed-in account: it ranks accounts by how fast their remaining quota must be spent to avoid resetting unused ([OMP's ranking](https://github.com/can1357/oh-my-pi/blob/main/packages/ai/src/auth/rank.ts)), with each session sticking to its account. When your pace cannot spend some quota before it resets, an orange line shows how much of the pool resets unused; hover lists it per account.

The top-right `0 resets` is the sum of available **banked reset credits**, from `rate_limit_reset_credits.available_count` in the existing usage requests. It does not count scheduled renewals, add network polling, or redeem credits. Missing/stale account counts produce `— resets`, never a fabricated zero. The count is authoritative even when a details list is incomplete ([official account/reset documentation](https://learn.chatgpt.com/docs/app-server)).

The pace comes from the past 30 **completed local calendar days**. For each date, sum the tier-weighted consumption across accounts; then average over dates with activity. A date used on two accounts counts once. Today is excluded, as are idle dates. At least two active dates are required. Historical account/lane records remain separate on disk, allowing this calculation without rescanning logs.

Balances and historical consumption are converted to a common nominal capacity: Pro 20x = 1, Pro 5x = 0.25, Plus = 0.05. Thus 100% of a Pro 5x allowance contributes one quarter of a Pro 20x allowance. Labels follow [CodexBar's provider mapping](../../Sources/CodexBarCore/Providers/Codex/CodexPlanFormatting.swift); relative tier sizes follow [official pricing](https://learn.chatgpt.com/docs/pricing). These are approximate nominal plan weights, not an exact billing conversion or a measurement of model-specific promotional limits. Unknown plans or simultaneous layered main quotas suppress the shared estimate rather than assume equal capacities.

The simulation spends the common historical daily rate on the account whose quota resets soonest, the order that strands the least quota and the one OMP's drain-first ranking approximates. Quota still left when its account resets counts as resetting unused; the reset restores that account's tier-weighted capacity. If everything is empty, the forecast waits for a known reset and reports the pool as empty now. The app does not switch accounts or infer which session uses which account.

Only the currently reported reset per account is simulated. The horizon stops before a second, unreported refill could occur, capped at 30 days. `covers past Thu` means the pool lasts through that horizon. Future banked-reset grants and redemption are not predicted. Days ahead are assumed active. The forecast itself uses a small bounded event loop and at most 31 daily values per account; unlike the separate cost-history feature, it adds no requests, timers, or log scans.

The service's `gpt-reserve` additional bucket is a smaller-model fallback (`normal_model_slug` identifies Luna in the observed response; the upsell says the advanced models remain capped). The former generic “Reserve” row misleadingly suggested another general allowance. This bucket is omitted from the rings and the pooled forecast; it remains visible on hover. No inference request is sent to test access to it.

History records positive quota deltas from existing refreshes. The first reading is a baseline, not newly consumed quota. Scheduled and banked resets preserve past daily totals and establish a new baseline. Corrections within a cycle use a high-water mark to prevent double counting. Deltas spanning midnight are omitted rather than assigned to an invented day. No unobserved consumption or refills are fabricated; usage during app downtime and around resets may be missed, making the estimate optimistic. This is observed active-day consumption, not an exact provider billing ledger.

Compact quota history is retained across launches and settings changes in `~/.local/share/pace-bar/quota-history.json` (owner-only permissions, hashed account/lane keys, no credentials, emails, or transcripts). At most 128 lanes and 31 daily totals per lane are retained; a small atomic save runs off the UI actor once per existing Codex refresh. Shared Codex logs do not identify accounts directly, but T3's retained session cursors and imported-transcript mappings can attribute historical quota snapshots. The maintenance import below concerns **account-attributed quota history**, not token-cost history. Cost history now imports automatically through the separate cache described above. Shared runway estimates still need attributable quota history across at least two active dates.

### Backfill existing T3 history

Quit Pace Bar before importing so its in-memory history cannot overwrite the import. From `PaceBar/`:

```sh
history_dir=$(mktemp -d)
python3 scripts/quota_backfill.py --output "$history_dir/quota.json"
swift run PaceBarProbe --import-history "$history_dir/quota.json"
rm "$history_dir/quota.json"
rmdir "$history_dir"
open "$HOME/Applications/Pace Bar.app"
```

The extractor reads T3's database read-only, maps provider instances through their configured auth homes, and reads the last 30 days of Codex quota metadata. Unmapped or conflicting sessions, copied pre-fork history, unrelated model lanes, and contradictory quota-cycle ownership are excluded. Child sessions inherit an unambiguous parent's mapping. Source files and identical snapshots are deduplicated. The temporary file contains quota metadata and account IDs with owner-only permissions; it has no tokens, emails, or conversation text. It is removed after import.

The importer checks each account against a fresh quota response, requires the same plan, and matches quota duration rather than primary/secondary field position. Reset timestamps within 60 seconds are treated as one cycle to tolerate provider timestamp jitter. Daily overlaps use the larger observed total rather than adding duplicate consumption; repeating an import is safe. Current live baselines are preserved. This recovers observed quota consumption, not a complete billing ledger; unresolved history is omitted and account-slot sign-in changes outside retained metadata may limit attribution. Reserve is not inferred from another model's allowance.
